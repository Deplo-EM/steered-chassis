## 下一步：先判角度，再查哪一轮

1. **先只读核对角差，保持右下急停。** 让现场用户确认截图时云台指向与车头是否确实差约 90°。若不清楚，请在车架固定、驱动力可靠隔离的条件下，让现场人员按安全规程对齐云台与车头，读取仍在更新的 `s_robot → peer_input_ → yaw_joint`。不要手推带电轴；断掉驱动供电可能让反馈停止，旧缓存不能拿来校准。若用遥控低速对齐，先在分离档、轮组架空且人员远离转动部件，完成后回急停再读数。
2. **物理与软件角度一致**：约 94° 的偏角说明跟随有转动请求，不能据此说零点错。先在两者对齐、读数接近 0 时验中档回中，再用小偏角验证纠偏方向，复测新门控是否消除单轮先滚。**物理已对齐、读数仍约 94°**：优先核对 yaw 零点和方向，勿用大死区遮掩。云台 `Gimbal/Instance/component/ins_motor.cpp` 当前 `kYawDir=kDirFwd`、`kYawAngleOffset=1.60879f`；驱动在 `Gimbal/src/motor_DaMiao.cpp` 用 `angle_=normAngle(actual_ang-angle_offset)`。以物理零位的有效电机反馈确定偏移，另核实逆时针为正；不要直接把截图的 `1.6423` 当作新 offset。只改 yaw 标定参数时重烧云台。
3. **角差已正常，但仍单轮持续滚**：先急停，记实际轮位（左前/左后/右后/右前）。安排一次短时、架空的观测，记录 `s_robot.ramped_.w`，各轮 `s_steers[i].angle_`、最终 `desired_angle`（从底盘 `chassis_ → solver_ → command_[i]` 找），以及 `s_wheels[i]` 的目标电流/速度反馈。索引顺序 LF、LB、RB、RF，当前 ID 为 1–4。必要时查 `s_wheel_frame`（CAN `0x200`，4 个有符号 16 位字段）；软件零命令与轮胎仍持续滚应分开排查，不能靠增加电流、放宽角度门或禁用保护验证。注意急停后的输出已经归零，不能把这时的零值当成故障发生时的采样。
4. **再出现不动或掉回 `Dead`**：先看两板 `state_`、`uwTick`；只有出现新的复位或自检失败证据，才回查 `g_reset_by_iwdg`、`can_tx_guard_.faulted_`、`s_imu.stale_gyro_`、电机/对板在线状态。历史失败累计非零不能代替当前锁存值。上电自动主动回中仍未实现，不能用是否回中判断烧录或 `Working`。

遥控：右下急停、右中/上允许控制；左上分离、左中跟随、左下小陀螺。小陀螺回中也有最小自转目标。两板上电/掉线恢复后，应先给有效右下急停确认，再解除。车架架空固定，异常持续滚、摆动或异响即急停并按现场规程断驱动力。不要在驱动力接通时 Halt、下断点或改写 RAM。

用户随后报告推左摇杆时舵轮朝向和轮胎都没动。实测急停下 `remote_input_.lv` 随杆变化并回零；随后在分离档的一次 Ozone 快照中，同见 `state_=kWorking`、`estop_=0`、`remote_source_=kGimbal` 和非零 `ramped_.vx`。这证明该快照里遥控转发和底盘速度目标生成均已通过；不代表电机收到了指令，也不代表故障全过程中 `Working` 没中断。该次短试的实际动作待用户反馈。

下一步先在急停下核对底盘 `rx_header1` / `rx_header2` 的 `StdId`：两路接收均按 ID 分发，所以 `motors_online_=1` 不能证明发送口正确。当前配置期望 CAN1 有舵电机反馈 `0x205–0x208`，CAN2 有轮电机反馈 `0x201–0x204` 和板间数据；CAN2 也可能看到 yaw 反馈 `0x11`。最近一帧会被覆盖，单次没看见某 ID 不能证明它不存在；只有正向读到对侧电机反馈才支持路由不匹配。用 Watch 展开父结构读成员，或在确认 ELF 对应目标后用 Memory 只读。尚未取得这两路实测 ID，不要先改路由。

若端口匹配而短试仍不动，优先同步观察一次 `ramped_.vx`、`s_steer_frame`（转向输出）和 `s_wheel_frame`（驱动输出）。新对齐门只拦轮速环，转向仍算输出：转向帧有命令但舵角不变，应先查转向命令能否送达对应电机；舵角变而驱动帧全零，则查哪个受驱轮的最终等效舵角误差超过约 20°。两类帧在急停时全零是预期，不能拿停后的零值判故障。不要为采样而 Halt、直接写电机命令或调大保护阈值。
