# 云台 PID 整定与三模式动态验收

**当前暂停调参和通电试车。** 已报告两次 Yaw 自转和遥控急停失效，先按[停机事件复核](35-Yaw异常转动与急停失效.md)留证、验证保护。本页步骤在恢复条件满足后使用。

**先解决云台明显过冲和首次俯仰迟滞，再落地做三档动态验证。** 这是 [现场总计划](31-现场调试与考核收尾计划.md) 的必做步骤。依据《Hello World 电控组步兵（舵轮）考核说明（已补全）》第 6–9 页：所有档位的平移以云台朝向为基准；云台两轴闭环须稳定；想拿“良好”还要看切档与 PID 表现。额外的整定记录文档是加分项。

DSH 可按[交接文件](33-DSH云台PID与动态验收交接.md)先准备空载云台 PID。底盘锁死仍由 Codex 跟进，完整回归排在云台小幅整定之后、整车落地和最终验收前。保护保持启用，短测中再进 `Dead` 就停试留证。

## 1. 同一车、同一固件，先录俯仰与 Yaw 基线

1. **固定台架、四轮离地，先能急停和切断动力。** 两板原车连线都保留。左拨杆上档分离，左杆、拨轮居中。云台保持在有充分上、下机械余量的位置，只试小幅。不要边动右杆边操作电脑。
2. **先用原云台固件作对照。** 保留现用底盘与云台固件。用实际已烧云台 ELF 对应的 Ozone 工程；[默认云台工程](../debug/ozone/gimbal.jdebug) 与 [axis-tune 工程](../debug/ozone/gimbal_axis_tune.jdebug) 指向不同版本。没证据确认板上是哪版时，从烧录记录核对，别拿本地源码或任意 ELF 的变量读正在运行的板。
3. **Ozone 只用来记录。** 打开匹配 ELF 的工程，先清旧断点。J-Link 接云台板，选 `Attach to Running Program`，确认 `CPU running`。Watch 用来确认 `s_robot.state_`、`s_robot.estop_` 和 `uwTick`。首轮 Pitch 在 **Data Sampling → Setup → Add Expression** 放四项：`s_robot.output_enabled_prev_`（授权）、`s_gimbal.pitch_target_`（目标）、`s_gimbal.pitch_feedback_`（反馈）、`s_pitch_motor.torq_input_`（力矩请求）。从约 100–200 Hz 开始，频率按探针实际能力选择，录完看 Timeline 或导出 CSV。Watch 的 5 Hz 刷新不能量首次动作延迟或过冲峰值。若动态采样不可用，固定手机拍遥控杆和云台（能同框就同框），先做可比的目测记录。[SEGGER Ozone 文档 §4.6](https://www.segger.com/downloads/jlink/UM08025_Ozone.pdf#page=116)
4. **俯仰三段比较。** 第一次从冷启动开始，右下急停、车和云台静止，等两板 `Working` 后右拨杆移中，输入回中时先看是否自行下沉或乱动。然后用右杆上下给一个小角度变化（如远离限位时约 10°），松手并记录。稳定后从相近角度重做一次；再在同一次开机内重新急停、解除后做同样动作。三种结果分别判断冷启动、每次重新授权和正常闭环跟踪。需要记录完整冷启动时，把采样准备好；只有一个探针时可分两轮分别采底盘和云台，不把两块板各自的 `uwTick` 直接相减。
5. **Yaw 独立比较。** 左杆、拨轮居中，只小幅横推右杆再回中，左右方向各一次。先对比目标停止后的实际峰值和回摆；保持同一姿态、相近目标幅度、同一台车和固件。先得到清楚的一组曲线，再根据证据选要改的环。

| 观察位置 | 需要的字段 | 能回答的问题 |
|---|---|---|
| 云台板 `s_robot` 与 `s_imu` | `state_`、`estop_`、`output_enabled_prev_`、`s_imu.calibrated_`；如接收机在云台，再看 `remote_input_.rv` | 在何时允许输出；右杆竖向有没有进死区外。可先用 Watch 看这些状态。 |
| 云台板 `s_robot → peer_input_`，及 `s_gimbal` | `peer_input_.pitch_target`、`s_gimbal.pitch_target_`、`pitch_feedback_` | 区分底盘没发新目标、云台未应用、反馈迟滞。真要算角度误差，反馈按 `pitch_feedback_ - kPitchJointOffset` 比较；当前源码偏移为 0。 |
| 云台板 `s_pitch_pid` 和 `s_pitch_motor` | `output_`、`integral_`、`s_pitch_motor.torq_input_`；有条件再看 `pitch_joint_rate_` | PID 想给多少、电机对象计算的最终请求值、是不是积分缓慢托起或接近限幅。请求值不能证明 CAN 送达或实际力矩。 |
| 云台板 `s_gimbal` 与 `s_yaw_pid` | `yaw_target_`、`yaw_world_feedback_` 和 PID 的 `output_`；旧版没有该反馈字段时看 `s_imu.euler_[2]` | Yaw 世界角和稳定后的目标比较。跨 ±π 按最短角看，关节角 `yaw_feedback_` 不能和世界目标直接相减。 |
| 底盘板（从端点向上回查时） | `s_robot.remote_input_.rv`、`gimbal_pitch_target_` 和 `state_` | 如果云台没收到变化，底盘有没有认到摇杆并生成目标。 |

首次俯仰迟滞分开判：

| 看到的先后关系 | 先做什么 |
|---|---|
| 上电后 `Working` 或输出授权还没到，目标不动 | 正常的上电流程包含约 2 秒 IMU 静止采样及两板自检（各板还有约 500 ms 的恢复阶段，实际总时长受启动和反馈影响）。在右下急停等就绪。若明显更久或反复退回，查 IMU、对板在线、电机反馈、急停授权；此时改 PID 不会缩短等待。 |
| 已授权，右杆非零，但底盘目标不走或云台端没收到 | 按“摇杆 → 底盘目标 → 云台收到的目标”定位。只在小到触发死区或朝软限位外推时不变是合理的；把目标一直增长很缓的情况记下来。当前俯仰目标随摇杆幅度积分，底盘的 `kGimbalPitchRate = 2.0` rad/s 是满杆的目标速率，不是机械速度；例如死区处理后 0.1 的输入，目标 0.5 s 只走约 5.7°。 |
| 两板都就绪，目标已变，PID 或电机命令接近零／被阻断 | 看急停、授权和俯仰是否在软件端点；比较 PID 输出和实际电机命令。不要用加增益越过限位或绕过门控。 |
| 目标已变、已有非零力矩请求，第一次慢；抬起比压下明显困难，积分慢慢增加才起动 | 对比重新急停再解除是否也出现。朝重力方向和逆重力方向分别测。位置接管会清积分，当前没有额外重力补偿；配重、摩擦和静摩擦都是候选原因。停动力后按台架方法查机械，别先提高 `Ki` 或力矩上限。 |
| 误差大、输出长时间接近 ±3.5 N·m，反馈仍跟不上 | 先停查负载、干涉、电机模式、反馈和实际扭矩余量。复核电机命令，增大 P 不会给已经饱和的输出增加可用力矩。 |
| 上下都慢、位置误差大、输出远未饱和且授权连续 | 这是可以试小幅改 Pitch P 的情况；按下节一次只改一项。 |

正常工作时的响应应按 `遥控输入变化 → 云台目标开始变化 → 反馈开始变化 → 稳定` 分段记录。若输入变化发生在授权前，单独记为启动等待。刚解除急停会从近似当前角接管；松右杆后保持角度，不自动回水平。

当前云台通过 MIT 报文的力矩字段发送外层 PID 结果，没有单独叠加前馈。台架架空会改变轮胎负载，但云台自身的惯量、重力和摩擦仍在，所以对比要保持俯仰起点与动作幅度接近。

## 2. 真正调 PID：一次只改一个量

**先整定云台 Yaw 和 Pitch，再看底盘舵角、轮速，最后才调跟随外环。** 先排除方向错误、反馈不可信、机构阻滞和保护停机。用同一初始角和相近目标幅度，记录峰值越过角、稳定时间、稳态误差、是否顶限；失效就急停，不继续加大幅度。队里没有给出定量阈值时，先以稳定保持、无明显回摆为台架通过条件，记录实测数字再比较，不把一次肉眼观察当成验收。

| 回路与文件 | 什么证据下动哪一项 | 观察与回退 |
|---|---|---|
| 云台 **Yaw**：[Gimbal/Instance/component/ins_pid.cpp](../Gimbal/Instance/component/ins_pid.cpp) → `kYawPidKp/Ki/Kd` | 反馈越过已稳定目标、随后来回摆时，先选一种改法：目标变化正常且输出追得很猛，先小降 P；确认转速反馈平顺，且贴近目标时刹不住，再单独尝试小增 D。若停止输入后还慢慢越过，且积分贡献明显，才单独降低 I。 | 仅当已确认用当前源码这组 **2.5 / 0.2 / 0.24** 时，可用 **P 2.5 → 2.3** 做一轮对比；回退后才比较另一方案。电流噪声式抖动、到位变差或出现新停机就退。 |
| 云台 **Pitch**：同文件 → `kPitchPidKp/Ki/Kd` | 先证实是反馈慢而非授权或目标慢。未饱和、上下都跟不上，可小增 P；已有过冲先处理阻尼。I 只拿来处理稳定后的持续位置偏差；俯仰要顶住重力，不能照搬 Yaw 的 I。 | 仅当已确认用当前源码这组 **3.6 / 1.0 / 0.20**，且“上下均慢、输出未顶限”成立时，可用 **P 3.6 → 3.8** 对比。两方向都检查首次与再次动作、峰值、保持偏差。 |
| 底盘 **舵角**：[Chassis/Instance/component/ins_pid.cpp](../Chassis/Instance/component/ins_pid.cpp) → `kSteerPidKp/Ki/Kd` | `s_solver.command_[i].angle` 是限速后的目标，`desired_angle` 是最后要到的位置，和 `s_chassis.steer_feedback_[i]` 对照。只有实测越过已稳定目标才按舵角超调处理。四轮共同过冲时，在电流版减小 P 或在干净速度反馈下小增 D，一次一个。单轮才异常先查该轮反馈、零点和机械。 | 测四轮同批动作，确认无明显回摆、`align_blocked_mask_` 不持续阻挡，轮胎在未对齐时不抢跑。保持现有电流模式及限幅。 |
| 底盘 **轮速**：同底盘文件 → `kWheelPidKp/Ki/Kd` | 舵都对齐、轮速确实振荡才动轮速环；用 `s_chassis.wheel_velocity_[i]` 和 `s_wheel_pids[i].output_` 辅助判别。四轮一起出力忽有忽无时，先看对齐门控、轮速饱和或逆解目标。 | 用小而一致的平移输入，观察四轮转速和输出；先把方向、稳定性调好，再做有载比较。 |
| **跟随外环**：[Chassis/RobotModules/component/robot.cpp](../Chassis/RobotModules/component/robot.cpp) → `kFollowKp/Kd` | 只有当云台独立保持正常、转向轮组稳定、底盘跟随角误差仍反复越零时，才调外环。先核实相对 Yaw 的方向、零位和底盘陀螺正负；跟随过强可小降 P，速度反馈可靠后才考虑单独加阻尼。 | 架空只能看舵/轮输出组合，跟随误差是否收敛须在许可的低速落地验证；一次只调一项。 |

实际操作：**保存 A 的源码和 ELF → 记基线 → 只改对应文件的一个系数 → 另建目录编译 B → Ozone 烧对应板、Reset & Run → 同动作复测 → 留更稳的一版**。不在运行中通过 Watch 修改增益。原始 Ozone 工程可能指向旧 ELF；用副本将 `File.Open` 指到 B 并确认标题栏。若 A 是旧云台固件、B 是旧库上完整的轴调候选，它们的算法和多个系数都不同，只能比较整体；要判断单项增益，A/B 必须用同一份源码和构建选项。新代码里云台也有 IMU 采样修复，不能把一次全量重编的差异归给一个 PID 数值。

从仓库根目录用 PowerShell 编译另存的候选。在同一次比较中只选要更换的板执行对应代码块，不覆盖常用 ELF。

```powershell
$out = Join-Path (Get-Location) 'Gimbal/build/pid-field-B1'
cmake -S Gimbal -B $out -G Ninja -DCMAKE_BUILD_TYPE=Debug "-DCMAKE_RUNTIME_OUTPUT_DIRECTORY:PATH=$out"
if ($LASTEXITCODE -eq 0) { cmake --build $out --parallel }
```

```powershell
$out = Join-Path (Get-Location) 'Chassis/build/pid-field-B1'
cmake -S Chassis -B $out -G Ninja -DCMAKE_BUILD_TYPE=Debug -DROBOT_STEER_CURRENT_FIELD=ON -DROBOT_STEER_MODE_PROBE=OFF "-DCMAKE_RUNTIME_OUTPUT_DIRECTORY:PATH=$out"
if ($LASTEXITCODE -eq 0) { cmake --build $out --parallel }
```

核对构建成功后烧对应新路径里的 ELF。每次保留急停、离线保护、Pitch 软限位和电流/扭矩上限。某块板有改动，就重新验证该轴的表现、相关模式、急停及启动；不得将“换了某个 P 后没试过另一侧”记成通过。

## 3. 三档动态验收：记录方向、稳态与切档

三档是左拨杆互斥档位。这里把“分离小陀螺”“跟随小陀螺”落实为：分别验证分离时云台独立保持、自旋时云台保持，再验证两类进出小陀螺的切换。**分离和跟随是两种不同的车头行为**；小陀螺持续自旋时，车头不会同时锁定对准云台。无论在哪档，平移方向始终看云台当前指向。

先完成静止、架空小幅、急停与限位检查，以及[底盘停机完整回归](31-现场调试与考核收尾计划.md#2-稳定台架复测验证底盘停机问题)。再到允许的空旷区域做低速落地对比。用地面固定标记或定机位视频标出云台前方、左侧和车体中心，测试者不站进运动范围。小陀螺先从**拨轮居中**的当前最低设定开始。首次只有短动作；稳定后换几个车头角度复测。第一轮拨杆切档前先急停、回中。

| 必测项 | 做法与通过标准 |
|---|---|
| **分离：平移与云台独立** | 左上，拨轮居中。云台先对固定参照，左杆小幅前／后和左／右，车沿云台轴走，云台目标保持时实测朝向不随底盘明显摆；右杆单独横转时，底盘已停稳不持续跟过去。前面通过后，可以在允许的低速范围单独小幅拨轮让车身转一点，看右杆回中时云台是否仍保持。再复做已出现过的转云台、左移/前移与松杆场景，不能意外进 `Dead`。 |
| **小陀螺：定向与反向** | 右杆回中，让云台保持朝固定参照。先确认只自旋时车体中心没有持续漂走；再按前、后、左、右分别短推，每次先让平移减回零。选择几个不同车头方位重做：前后两条轨迹应方向相反，左右两条也应相反，旋转一圈中的车头变化不应把平移轴一起带着转。稳定后做一次前→回中→后或左→回中→右：允许短暂减速和对舵，不应逆向大窜或周期性甩偏。若考核需演示底盘反向自旋，先退出并停稳，再在受控条件下另测反向，不在首轮突然方向反打。 |
| **小陀螺：云台稳向** | 右杆、左杆回中先测低速纯自旋；通过后再加入小幅前后/横移。看固定参照和 Yaw 目标/反馈：相对底盘的关节角持续改变是正常的，外部观察的云台朝向应稳定，无持续绕着车身跑、显著来回摆或失锁。Pitch 当前是关节角闭环，在平坦台架或地面看上下稳定；车身颠簸时，它不能当作世界垂直姿态补偿。 |
| **跟随：收敛与平移** | 左中，小幅横转云台后松右杆。从云台在车头左右两侧分别测：车头应向正确方向靠拢，误差收小后不反复跨过云台指向。加一点左杆时，平移仍按云台方向；不因追角出现大幅抖动或意外停机。 |
| **分离 ↔ 小陀螺、跟随 ↔ 小陀螺** | 先右下急停、各轴回中、换档，再短试。进入小陀螺验证自旋受控上来；退出到分离不继续保留自旋；退出到跟随，车头应重新趋向当下云台方向，不能沿旧自旋持续跑、反向长甩或来回找正。急停会撤销输出并在重新授权时按实测接管，不以“恢复到急停前旧目标”作为通过条件。 |

经过急停的换档能验证两档各自的启动和恢复行为，不能证明连续切档无突跳。如果考核要求演示后者，以上各项先通过，再按现场允许的低速流程单独评估。两杆与拨轮回中，在能够立即急停和切断动力的条件下，比较切档前后自旋的增减、退出时的云台保持以及跟随误差。合格时底盘方向不跳、舵角不过度回摆，跟随误差收敛。结果单列，未做就不打勾。

判断方向时看地面运动的**车体中心轨迹**，以及开始和结束的云台朝向。轮组瞬时转向、单个车轮的正负和车体朝前方向都不足以单独判错。先判沿要求方向的位移正负，再记录侧偏和周期性摆动；例如沿要求方向 40 cm、侧偏 3 cm，平均方向偏差约 4°，弯曲轨迹另记最大侧偏。Yaw 记录对固定参照的峰值偏差和趋势，跟随记录误差最大值、是否反复过零与稳定时间。小陀螺各方向每项做至少一次，第一轮均稳和安全后再重复两轮；不能稳定重复就标为待调。

| 若失败 | 先查哪条链路 |
|---|---|
| 分离、跟随和自旋里都固定向错误方向移动 | 先核对云台相对车头角 `s_robot.peer_input_.yaw_joint` 的零点、正负与遥控映射，再查轮位、舵角/驱动方向；别先动 PID。 |
| 分离方向对，小陀螺移动却周期性断续或偏 | 对照底盘 `s_solver.chassis_motion_`、各 `command_` 与 `s_chassis.align_blocked_mask_`。可能是轮组在某些方位跟不上或对齐门反复挡车，也可能是饱和、间隙或旋转时 Yaw 漂移。先看是目标向量错、反馈跟不上还是门控，保留门控与限速。 |
| 云台在车不转时就过冲，或只在自旋时朝向漂 | 前者先整定 Yaw；后者看右杆是否为 0、世界目标是否保持、反馈/力矩有没有饱和、姿态或反馈是否失效。不要用跟随外环补云台自身的问题。 |
| 云台稳，底盘跟随却反向或左右反复摆 | 反向多半先查符号、反馈和零点。方向正确后才用波形决定是否调跟随的 P 或阻尼。 |
| 任一档再进 `Dead`、急停后还主动出力、发生卡碰或明显异常温升 | 立即按总计划停机；只在安全之后看 `causes`、`tick_ms`，含 8 再看 `last_imu_dead_.imu.reason`。处理故障后重新验证，不把停机或锁存当成 PID 参数。 |
