# 架空过冲与俯仰响应复测

现场操作优先用 [云台 PID 整定与三模式动态验收](32-云台PID整定与三模式动态验收.md)。本页用于核对旧版和 `axis-tune` 候选之间的参数与响应差异。

现场基线：原底盘电流版已实测分离、跟随、小陀螺，操作者观察到三档符合预期。现场同时观察到 Yaw 和舵轴先过头再回摆、Pitch 追角偏慢。新候选只做过主机回归和固件构建，机械响应待现场与基线对比。架空会改变轮胎的负载和摩擦；云台自身惯量并不随架空消失。MIT 报文虽有「前馈力矩」字段，本代码用它传反馈 PID 的结果，没有额外的重力或速度前馈。

| 单独验证 | 新 Ozone 工程 | 回退工程 | 变化 |
|---|---|---|---|
| 云台 Yaw、Pitch | [gimbal_axis_tune.jdebug](../debug/ozone/gimbal_axis_tune.jdebug) | [gimbal.jdebug](../debug/ozone/gimbal.jdebug) | Yaw 的 P/I/D 从 2.5/0.6/0.12 改为 2.5/0.2/0.24，用 IMU 换算的世界 Yaw 转速做 D；Pitch 从 3/1/0.15 改为 3.6/1/0.20，用关节转速做 D。各轴仍限 ±3.5 N·m。 |
| 底盘四个舵轴 | [chassis_axis_tune.jdebug](../debug/ozone/chassis_axis_tune.jdebug) | [chassis_steer_current_field.jdebug](../debug/ozone/chassis_steer_current_field.jdebug) | 电流版舵角 P/I/D 从 10000/2000/150 改为 10000/1000/600，D 用舵轴实测速度。维持 CAN1 `0x1FE` 和 ±1.2 A；轮速环与对齐判据沿用基线。 |

Yaw、Pitch 的参数文件是 `Gimbal/Instance/component/ins_pid.cpp`，四舵参数文件是 `Chassis/Instance/component/ins_pid.cpp`。这轮不调整跟随外环、摇杆目标速度、机械零位或软件行程。

1. **先测云台。** 车架稳固架空，确认俯仰部件的活动范围没有干涉；右拨杆下档，左拨杆上档分离，拨轮居中。只接云台板，停止旧调试会话，打开新云台 Ozone 工程，按 `Download & Reset` 并观察 `CPU running`。随后解除急停。左摇杆始终不动，先用右摇杆左右各轻拨一次、松开，比较摇杆松开后的最大摆幅；然后用右摇杆上下给同样大小的小角度变化，比较实测 Pitch 追上目标的时间。避免靠近机械端点，也不要边试边在线写 PID。
2. **再测底盘。** 右拨杆先回急停，只更换底盘，打开新底盘 Ozone 工程。仍在分离档，右摇杆和拨轮居中，左摇杆小幅斜推保持固定方向，观察四个轮组的朝向是否还有明显来回摆；轮胎沿滚动方向转动不算舵角变化。再松手急停。随后复查三档与遥控急停；若无稳固架空条件，先保留基线，不做这一轮带动力试验。
3. **先看目标，再判过冲。** Ozone 云台展开 `s_gimbal`：Yaw 看 `yaw_target_` / `yaw_world_feedback_`，跨 ±π 要按最短角理解；Pitch 看 `pitch_target_` / `pitch_feedback_`（当前附加关节偏移为零）。底盘展开 `s_solver.command_[0]` 的 `angle` / `desired_angle` 与 `s_chassis.steer_feedback_[0]`，角度比较也按最短角；其他三轮同理。实测越过已经稳定的目标再回来，才是该位置环的过冲。若 Pitch 目标本身走得慢，查 `gimbal_pitch_target_` 和摇杆命令速率；若目标到了、反馈慢且长期顶到输出上限，优先查配重、摩擦或扭矩余量，不直接加大限幅。
4. **记录对比再落地。** 用相同的小动作记最大越过角与稳定时间，也记录有没有新的抖动、持续偏差或 `Dead`。哪一块变差就急停并回退那一块。架空结果正常后，再在可安全停车的空旷区域做低速分离、跟随、小陀螺与急停验证；轮胎接地的性能需要单独确认。

这里「只接云台板 / 底盘板」指 J-Link 连对应板，车上的双板通信仍保持接通。测完一块再切换 J-Link。`Stop Debug Session` 只用于离开调试会话，停车用遥控急停。

Pitch 松手保持最后的角度；解除急停时目标从实测位置接上，正常逻辑不会强制回到水平。

离线验证：两板 CMake/Ninja 构建完成，Ozone 工程均指向各自 `build/axis-tune` 下的 ELF；现场基线两份 ELF 的 SHA-256 与调整前一致。主机回归的通过只证明报文与控制逻辑，不能代替实车阻尼和俯仰响应验收。
