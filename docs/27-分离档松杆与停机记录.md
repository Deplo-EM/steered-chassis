# 分离档松杆与停机记录

考核依据：`D:/ForTest/Hello World 电控组步兵（舵轮）考核说明（已补全）.pdf` 第 6 页。§3.1 分离档由遥控器决定底盘运动，车身不自动跟随云台；§3.2 约定所有档位的平移以云台朝向为前、云台左侧为左。拨轮居中时，分离档的车身没有自动转向指令；有平移时，舵角可随云台方向变化。左摇杆与拨轮都回中、减速结束后，仅转云台不应让舵角目标持续变化，也不应指令驱动轮持续滚动。减速阶段的滚动和舵机尚在收敛，不等同于停车后仍追云台。

现场记录：云台持续横转，分离档左移、前进交替，松左摇杆附近偶发底盘进 `Dead`。主机复现的是旧版在减速时仍旋转剩余平移速度的方向，没有复现实车的 `Dead` 根因。对齐尚未完成只封住行走输出；记录到舵向持续停滞才会触发相应 `Dead`。其他分支（CAN、遥控、IMU、电机、对板）也会停机。

候选底盘：[chassis_separate_release.jdebug](../debug/ozone/chassis_separate_release.jdebug)。这是 `0x1FE` 电流版，沿用上版舵向参数、轮速限制和对齐/停滞保护，不用重烧云台。分离档松左杆后，沿松杆前的车体系方向平顺减速；尚未停稳又推杆时先换算剩余速度，再回到实时云台方向。拨轮的车身旋转和其他两档维持原逻辑。原 [底盘轴调版](../debug/ozone/chassis_axis_tune.jdebug) 保留。

## 现场先看一条记录

1. 固定车架、四轮架空，右下急停后烧新的底盘候选，J-Link 只连底盘，双板仍保持互联。确认 Ozone 显示 `CPU running`。用左上分离、拨轮居中的条件，只做一次小幅左右/前进切换与松杆检查。出现异常立即回右下急停。若是已有一次事件，直接读取，不用复现。
2. 如果进 `Dead`，先不重启。在 Ozone 的 `Watched Data` 展开 `s_robot → last_dead_`，以十进制读 `causes`，并记录 `tick_ms` 和 `left_centered`。该记录在急停确认后继续保留，上电复位后清空；`causes=0` 表示这次启动尚无记录，可配合 `uwTick` 判断是否发生了复位。

| `causes` 位值 | 含义 | 对照项 |
|---:|---|---|
| 1 | 舵向停滞锁存 | `s_chassis → last_steer_stall_ → stall_mask`，`steer_stall_sequence` 应与舵向快照 `sequence` 一致；发送证据见 `g_steer_stall_tx`。 |
| 2 | CAN 发送监督故障 | `can_failed_cycles` 是当时累计失败周期；后续再调查具体总线或邮箱。 |
| 4 | 遥控不在线 | 结合遥控转发状态；可能与 64 一起出现。 |
| 8 | 底盘 IMU 数据不满足控制条件 | 查底盘 IMU 的校准、健康、新鲜度。 |
| 16 | 底盘电机反馈不满足条件 | 查电机在线状态及对应反馈。 |
| 32 | 云台不在线或不在 Working | 查云台状态和板间通讯。 |
| 64 | 缺有效急停授权 | 与其他位可能合并；例如 68 = 遥控失联 + 授权撤销。 |
| 128 | 状态值非法 | 保留现场快照。 |

现场多次记录为 `causes=8`，包括跟随档。新取证步骤见 [底盘 IMU 停机取证](29-底盘IMU停机取证.md)。

`vx_before_stop`、`vy_before_stop` 是限加速度后的平移指令，`w_before_stop` 是底盘自转指令，不是云台转速。`last_dead_` 只在进入 `Dead` 时更新，不能把急停以后已经恢复的实时在线标志当成当时证据。

离线验证：旧版在「松杆减速方向固定」回归上失败；第一版改动在「尚未停稳再推杆」回归上失败。当前底盘回归和全部主机测试共 1801 项检查通过，独立底盘固件构建成功。云台与前两版底盘 ELF 的 SHA-256 未变化。实车偶发停机还没有新记录，不能从主机结果认定已消除。
