# 舵向前馈停机与轮位复核

2026-11-16 · 对照 [38 号摩擦交接](38-转Codex-摩擦特调与下地阻塞.md) 和 [38 号下地清单](38-四轮版下地放行清单.md)。**目前不带动力下地。** 这轮只做离线对照，未修改固件、参数、ID 或连接实车。

## 为什么加前馈后更容易停

[底盘舵向闭环](../Chassis/RobotModules/component/chassis.cpp#L214)先算舵角 PID，再叠加 0.25 A 静摩擦补偿。低速、有角误差时补偿开启，机械卡点也满足这两个条件。随后，[堵转判断](../Chassis/RobotModules/component/chassis.cpp#L300)用的是**合成请求**：约 0.48 A 就达到出力门槛，还需同时满足角误差和 500 ms 无进展才锁存，并不要求电机输出达到 1.2 A 上限。加补偿后，PID 只需约 0.23 A 就能合计越过 0.48 A。

以当前舵向 PID、真实逆解器与电机类做主机对照，固定合格的编码器反馈与舵速度，输入 45° 舵向目标。下表仅证明软件行为，不能推定这台车的电机实际电流或也恰在 563 ms 停机。

| 配置 | 100 ms 时舵电流请求 | 1 秒内的结果 |
|---|---:|---|
| `dsh-reorder-4w`，无补偿 | 0.284 A | 等待对齐，未报堵转；1 秒时仍请求 0.301 A |
| `dsh-friction-B01`，0.25 A 补偿、堵转保护开启 | 0.534 A | 第 563 ms 锁存；舵和轮驱动请求归零 |
| `dsh-friction-nostall-B02`，0.25 A 补偿、堵转保护关闭 | 0.534 A | 等待对齐，未报堵转；1 秒时仍请求 0.551 A |

三份 ELF 的完整 SHA-256 与 38 号一致。编译定义也确认了上表的差别。三份都有 `SAFE-BUILD`；这个标记只代表故障注入关闭，不能用来判断堵转保护是否开启。**B02 不再通电试验；B01 也先退出试车候选。** 保留四轮基准作为离线对照。现阶段舵向摩擦补偿建议关闭，保留等效解翻转、整组对齐和堵转保护，优先排除机械刮蹭。不能拿关保护或加电流替代机械修复。

另有两个补偿实现问题：补偿叠在 PID 限幅及抗积分饱和之后，电机类虽仍夹到 1.2 A，但上层的补偿请求可以高于它；开关未限制在电流版，电压版没有采集该处所用的舵速，误开时会附加电压 raw，而不是文档所说的电流。以后确需在无卡点的机构上补偿，应单独评估小量平滑补偿、合成限幅和抗积分饱和，保持不进展保护；现有数据不能支持另猜一个非零值。

如果已有那次停机记录，只区分以下三种，不必为补记录重新上电：

| 同次记录 | 判断 |
|---|---|
| 仍 `Working`、`drive_ready=0`、`align_blocked_mask` 非零 | 对齐门在等待，不能记作进 Dead。 |
| `last_dead_.causes` 含 `1` | 舵向停滞；看同一事件的 `last_steer_stall_.stall_mask`。例如位 2（数值 4）只指代码索引 2，需先确认实际对应哪个轮。 |
| `causes` 含 `8`，或出现其他位 | 按实际停机原因查；IMU 读同次 `last_imu_dead_.imu.reason`。B02 本身不可能由被关掉的堵转判断产生这一停机。 |

## 跟随模式轮子歪，怎样区分

跟随档会用云台相对车头偏角和底盘陀螺计算 [底盘旋转速度](../Chassis/RobotModules/component/robot.cpp#L438)。[逆解](../Chassis/RobotModules/component/chassis_ik_solver.cpp#L167)把这份旋转分量与平移相加后分别给四个轮位。主机实测，四轮从零角起步，纯原地转时最终目标按左前、左后、右后、右前依次为 **−45°、+45°、−45°、+45°**（允许等效反向）；纯直行且 `w=0` 时四条滚动方向平行。无任何速度指令时会保留上次舵角。

因此只凭一个画面见四轮不平行，既不能判 ID 错，也不能判正常。用已有数据先看 `s_robot.ramped_.w` 和平移量，再比较 `g_chassis_dbg.steer_desired` 与 `steer_feedback`。只有确认是稳定的纯平移，软件目标都平行而实物还固定偏斜，才优先查轮位、零点或舵未跟上。平行按轮面看；角度差 180° 同时轮速反向是同一滚动方向。

## 映射：程序已核，实物还不能定案

直接读出三份 ELF 的两张 ID 表，均为 `{3,4,1,2}`；零点字节也完全相同。前馈版本没有把 ID 或零点换掉。补全版考核说明 §6.2 的零点按四个**物理轮位**列，不能按设备 ID 再重排一遍。

| 轮位 | 索引 | 候选轮/舵 ID | 手册零点 rad | 已有实物证据 |
|---|---:|---:|---:|---|
| 左前 | 0 | 3 / 3 | +2.61346 | 旧版排除索引 2 时观察到左前停住；未分开记录轮和舵 |
| 左后 | 1 | 4 / 4 | −2.06844 | 推定；没有独立定位记录 |
| 右后 | 2 | 1 / 1 | +0.00729 | 推定；没有独立定位记录 |
| 右前 | 3 | 2 / 2 | +1.58518 | 旧版排除索引 1 时观察到右前停住；未分开记录轮和舵 |

旧版两次排除同时屏蔽对应驱动和舵。它们无法证明 ID1 与 ID4 的后轮顺序，也无法证明一处的 M3508 与 GM6020 恰好同 ID。原地不转的慢速圆周摇杆给四组近似同一平移方向，这种顺畅不具备区分不同轮位排列的能力。

现在能做的是断动力后按物理轮位分别核对驱动和舵的现有标识、线束记录，优先左后和右后，不改电机内部设置。缺的标注为未确认；待 [停机门槛](35-Yaw异常转动与急停失效.md)通过后，再在受控架空条件把两类电机分别核清。**在那之前不盲换 ID、不改角度零点、不试落地。**
