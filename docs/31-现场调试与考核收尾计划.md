## 1. 先准备和整定空载云台

现在可用 [DSH 交接文件](33-DSH云台PID与动态验收交接.md) 和 [PID 基线步骤](32-云台PID整定与三模式动态验收.md)。先记现用两板固件，保持底盘版本。通电前确认车体固定、四轮离地、轮组不碰支架、急停和断动力手段可用；条件不齐就先做离线部分。云台短测用左上分离、左摇杆和拨轮居中，只小幅试右摇杆。两板仍需正常就绪和授权。

- [ ] 原云台固件先测 Pitch 冷启首次、同次第二次和重新解除急停，分清上电等待、目标生成和反馈跟踪。Yaw 只横推右杆再松，比较目标稳定后的峰值越过与回摆。
- [ ] 同一轮只改云台的一个参数，保存原 ELF。保持另一板固件和所有保护，任何新停机、复位、明显晃动或非指令动作先停试留证，交回 Codex。
- [ ] Yaw/Pitch 小幅动作稳定后，固定云台候选并进入底盘完整回归。可用同条件的 Yaw 前后数据做唯一加分项。

## 2. 稳定台架复测：验证底盘停机问题

- [ ] **烧录与上电。** 已烧 `imu-sample-fix` 的底盘直接保留。确需烧录时，动力隔离，待烧底盘控制板正常供电；车固定、四轮离地。遥控器开机，右拨杆下档急停、左拨杆上档分离、两杆和拨轮回中。J-Link 接底盘、原车板间线不动。开新版工程，核对 ELF 目录含 `imu-sample-fix`，按 **Download & Reset Program**，确认写入与校验成功，再确认 **Reset & Run / CPU running**。见 [SEGGER Ozone 手册 §5.3.1–5.3.2](https://www.segger.com/downloads/jlink/UM08025_Ozone.pdf#page=186)。烧录并确认运行后可以关 Ozone；需要查记录再用匹配的 ELF **Attach to Running Program**，不要用 Reset 或 Halt 查故障。
- [ ] **就绪与静止。** 恢复正常动力与反馈，保持急停、车和云台不动，等标定和自检。看到 `Working` 与急停同时成立是正常的；`Dead` 或 `Resurrection` 中也不应主动出力。确认零输入无持续滚动，再短试一次急停，确认所有轴停止主动出力。轮胎因惯性短暂滑行、俯仰机构失力后受重力下沉，与电机仍主动出力要分开判。
- [ ] **固定本轮固件组合。** 用上一阶段留下的云台版本复测底盘；本阶段不把换云台参数和底盘故障排查混在一起。
- [ ] **先看四个轮位。** 用分离档小幅前推和侧推，逐个确认左前、左后、右后、右前的舵向、零点与驱动方向；用轮胎接地点的预期运动方向判断。舵角约差 180°、轮速同时反向可能是等效解。观察到某轮持续摆、滚反或卡住，先停查实际反馈和轮位；不靠调 PID 掩盖方向、零点或干涉。

下表是本轮关键回归。拨轮一直居中。小幅、短时，每项松手后等车停稳；换档统一 **右下急停 → 所有输入回中 → 选左档 → 右拨杆中档短试 → 右下急停**。第一轮全过且时间允许，再按同顺序复做两轮。

| 勾选 | 操作 | 台架上看什么 |
|---|---|---|
| [ ] | **分离（左上）／只动左杆**：轻推前、左，分别回中 | 舵轮朝向与轮胎滚动组合符合云台方向；回中后减速，最终不再持续驱动。 |
| [ ] | **分离（左上）／只动右杆**：轻推水平，左杆不动 | 云台横转；底盘已停稳且拨轮居中时，车轮不持续驱动，舵向不持续追着云台。 |
| [ ] | **跟随（左中）／只动左杆**：从车头与云台大致对齐开始，轻推前、左 | 平移仍按云台坐标；可能叠加少量跟随修正。 |
| [ ] | **跟随（左中）／只动右杆**：小幅横转云台 | 轮组给出让车头趋向云台的转向组合。车架固定时看组合，不要求夹角变成 0。 |
| [ ] | **分离／组合松杆**：右杆轻偏保持云台横转，左杆短促左移再松、前进再松 | 回中后的剩余平移沿原方向减速；停稳后仅转云台不持续带动底盘。不再出现上次的偶发 `Dead`。 |
| [ ] | **小陀螺（左下）**：拨轮居中，短暂解除急停 | 轮组形成绕几何中心自旋的组合；即使两杆居中也有自旋目标。用右下急停结束，不连续架空旋转。 |
| [ ] | **云台两轴**：回分离，左杆及拨轮居中，右杆分别小幅左右、上下 | Yaw/Pitch 方向正确、松手后稳定保持，不反复摆动。Pitch 松手保持当前设定角，不要求自动回水平。 |

**通过条件：** 正常操作不进 `Dead`，无持续摆动、非指令动作、摩擦撞击或异常温升；急停能撤销输出。任何一项失败先停，不靠反复摇杆碰运气，也不跳过它去试落地。

**落地前必须通过的底盘回归：** 重复验证分离和跟随的单左、单右，以及分离档慢转云台时交替平移再松杆。正常操作期间无异常 `Dead`、无被迫重新授权、无意外复位。记录实测两板版本和结果。通过后如有舵角或轮速环问题，再逐项整定并重跑相关场景；跟随外环留到两轴和底盘各环稳定后评估。

### 再进 Dead 时，只抄必要信息

先回右下急停；若仍有主动出力，优先切断驱动动力。安全条件允许保留控制板电源时，再用 Ozone 只读连接。先看 `uwTick` 是否持续、`s_robot → last_dead_ → causes` 和 `tick_ms`。字段来自最近一次进入 Dead，先核对时间，避免把上一次当这一次。

| 看到什么 | 下一步 |
|---|---|
| `causes` 含 8 | 读 `last_imu_dead_ → imu → reason`（以及同一条 `tick_ms`）；若是 `kAccLow/kAccHigh`，再抄 `last_rejected.accel_mps2[0..2]`，过期类记录各 `age_ms`。不要放宽 20 ms 或坏样本阈值。 |
| `causes` 含 1 或 2 | 1 查 `steer_stall_sequence` / `s_chassis.last_steer_stall_`，结合目标和实际舵角；2 查 CAN 发送监督，保留总线与失败计数。不要先加输出或关闭保护。 |
| `causes` 含 4、16、32、64 | 顺序看遥控来源/转发、电机反馈、对板状态、右下急停确认；原因可以组合。检查时保留现在已知能用的接线配置。 |
| `uwTick` 反复归零；快照为空或旧 | 看 `g_reset_by_iwdg` 和复位前的控制状态；别连续点 Reset。重新上电会清停机快照。 |

若只在新固件出现明显回归，先留记录，再按急停、隔离动力的顺序回退**这一块板**。回退后重做台架关键项；此前能跑但进过 Dead 的版本不能跳过复验。[采样修复及字段说明](30-BMI088采样修复与现场回归.md)

## 3. 安全验收，再安排首次落地

以下先在受控台架做。独自调车时，如果无法独立切动力、隔离所需部件或安全记录，就把对应项标为“未做”，留到具备条件的台架场次，不在通电运动中拔插线、不用断点停 CPU 代替看门狗测试。

- [ ] **急停和重新授权。** 用小幅动作验证拨回右下后三类（驱动轮、舵轴、云台）都卸力。分别记录软件命令归零、实际出力撤销和轮胎停转，别用 LED 或 Ozone 会话是否断开代替。恢复遥控或重新上电时先在右下确认，摇杆回中、自检就绪后才解除，不能自动带动作恢复。
- [ ] **遥控失联。** 在可控台架操作规程下验证：关遥控器后离线归零、无继续主动运动；再开遥控时右下急停，确认重新授权流程。记录触发到归零及实际卸力；有仪器再量时间。
- [ ] **双板 CAN 失联。** 在隔离动力、可控断链的台架验证。区分板间链路与同总线上电机支路，确认对板识别离线、进入保护，恢复后仍按急停确认与自检。若断链让零指令送不到，另外记录各轴实物卸力的证据，不能把 CAN 提交成功或软件归零等同于电机卸力。
- [ ] **IWDG 独立证明。** 考核要求验证停止刷新或控制任务卡死后约 200 ms 复位。用 [台架故障验收清单](08-台架故障注入清单.md) 的受控方法，在电机动力隔离下测试需要验收的板；记录从停喂到复位的时间、`uwTick` 重新计时、`g_reset_by_iwdg = 1`。关遥控定性演示不能代替这项任务卡死/停喂验证。按考核要求准备演示方式；故障版测完恢复正常固件，确认故障注入关、无条件喂狗关。本轮现成的底盘候选已经是正常构建，别拿探针或故障版上车演示。
- [ ] **两轴完整能力。** 在队里确认的机械余量内验证 Yaw 过回绕点不反向长甩，活动范围确认后再验证连续一圈；Pitch 两端确认目标钳位、没有卡住持续顶推，反向能退出。限位数值在没核实行程前不改，不用贴着硬限位找零点。

**落地入口：** 第 2 节底盘锁死回归、各项台架基本功能和停机保护通过，有团队允许的场地与安全落地流程。先急停并按现场断电/动力隔离流程撤外接线、安放车体；按团队流程恢复供电与授权，清空活动区。低速试完一项停稳一次，不做随机满杆。没有明确条件就保持架空，不临时发明落地方式。

1. **分离：** 左上，拨轮居中。将云台与车头错开，短行前/后和左/右，确认车沿云台坐标走、车头不主动跟随、云台朝固定参照时不被底盘运动明显带偏。最后复查前/侧移交替松杆。
2. **跟随：** 左中，分别把云台偏到车头左右，车头应向正确方向靠拢、稳定后不来回找正；带小幅平移时仍按云台方向走。
3. **小陀螺：** 左下，拨轮居中先做低速纯自旋，观察云台水平朝向能否稳住。随后在不同车头角度各试前、后、左、右，并在一次平移先回中后验证反向。以地面轨迹相对云台判断。两杆回中仍可能自旋，退出靠急停后切档。
4. **切换复核：** 分离↔小陀螺和跟随↔小陀螺分别测。退出应撤掉旧的自旋目标；进跟随后车头应收敛到此时的云台方向。动作与判定见 [三档动态表](32-云台PID整定与三模式动态验收.md)。

## 4. 冻结、彩排、正式验收与收尾

- [ ] **定版。** 留存底盘/云台实际烧录的两份 ELF、SHA-256、源码版本、关键参数和现场结果；旧版保留。不要只记 `git HEAD`：构建时未提交的改动也可能进了板子。两板若用不同版本，分别记录对应源码和已验证的组合；无法对应时，在留有足够回归时间时建立可追溯的版本。上 GitHub 的是考核要求的源码和说明，经核对后由你提交并提供验收链接。
- [ ] **彩排一次全流程。** 先查急停和就绪；然后按“分离验证云台朝向平移 → 跟随对正 → 小陀螺与小幅平移 → 云台 Yaw 回绕、Pitch 限位 → 安全项目记录/演示”的顺序走完。验收当天按考核方顺序执行，可提前把安全证据准备好。再过一遍源码的 10 项：CAN 与电机、DBUS、PID、IMU、共享类型、逆解与坐标、两轴、双板协议、状态机与 1 ms 调度、IWDG。
- [ ] **现场结束。** 右下急停，按现场流程切断动力后断整车电源、撤调试线和支架、归还设备。保存考核反馈和剩余事项，明确记「通过／失败／未做」。主机通过、下载校验和档位能动各自只证明对应一步。

若只有一段短场次，优先完成 **云台原版基线与必要整定 → 底盘完整回归 → 安全演示 → 低速三档动态验收**。不在当天临时更换控制方案、重调所有 PID 或加入加分功能。时间不够或安全失败时，保留实测证据和明确的未做项目。
