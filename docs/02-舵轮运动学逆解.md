# 02 · 舵轮运动学逆解

> 这是整个底盘控制的核心公式。看完你应该能回答：为什么每个轮子要"算角度 + 算速度"、
> 为什么会有"翻 180° 反而更好"、以及代码里每个 `if` 是在防什么。

---

## 1. 先说清楚"逆解"是什么

| | 输入 | 输出 | 谁用 |
|---|---|---|---|
| 正解 | 8 个电机的转角/转速 | 车在往哪走、走多快 | 仿真、状态估计 |
| **逆解** | 车想往哪走 (vx, vy, w) | 每个轮组该朝哪、转多快 | **我们的控制器** |

舵轮和麦轮最大的区别：

```
麦轮：4 个轮子方向固定        舵轮：每个轮子自带一个转向电机
      ┌───┐ ┌───┐                  ┌───┐ ┌───┐
      │ ╱ │ │ ╲ │                  │ ↖ │ │ ↗ │   ← 轮子可以转到任意方向
      └───┘ └───┘                  └───┘ └───┘
   逆解 = 一组固定线性方程        逆解 = 每个轮组各解一个「方向 + 大小」
```

正因为方向是自由的，舵轮能横着走、斜着走、原地转，但代价是**必须自己处理方向的多解问题**。

## 2. 记号与几何

### 2.1 车体坐标系

```
              y（左）
              ↑
   LB ●───────┼───────● LF      hl = 0.167 m（前后半距，说明书 6.2）
      │       │       │         hw = 0.167 m（左右半距，与 x 相同 → 正方形）
      │       │       │
 ─────┼───────┼───────┼────→ x（前）
      │       │       │
   RB ●───────┼───────● RF
              │
```

> 轮半径 R = 0.066 m（直径 132mm）。四个轮组的坐标是
> LF(0.167, 0.167)、LB(−0.167, 0.167)、RB(−0.167, −0.167)、RF(0.167, −0.167)。

轮组编号（与 `GetMotorWheel(i)`、逆解数组下标完全一致）：

| i | 名称 | 位置 (x, y) |
|---|---|---|
| 0 | 左前 LF | (+hl, +hw) |
| 1 | 左后 LB | (−hl, +hw) |
| 2 | 右后 RB | (−hl, −hw) |
| 3 | 右前 RF | (+hl, −hw) |

### 2.2 输入输出

- 输入：`(vx, vy, w)`，其中 `(vx, vy)` 在**云台坐标系**（单位 m/s），`w` 是车体角速度（rad/s，逆时针为正）。
- 输出：每个轮组的 `{ speed, angle }`
  - `speed`：轮子线速度（m/s），正 = 沿当前舵角向前滚
  - `desired_angle`：未经速率限制的最终等效方向，驱动门用它与实测角比较；
  - `angle`：舵角（rad），车体 +x 起逆时针为正，**连续角**（可以超过 ±π）

## 3. 推导（四步）

### 第 1 步：云台系 → 车体系

（详见 `docs/01` 第 2.4 节，这里只写结论）

```
δ = 云台朝向 − 车头朝向
vx_c = vx·cosδ − vy·sinδ
vy_c = vx·sinδ + vy·cosδ
```

### 第 2 步：刚体上一点的速度 = 平动 + 转动

车体以角速度 ω = w·ẑ 旋转，轮组在位置 r = (x_i, y_i)，则轮心速度

```
v_i = (vx_c, vy_c) + ω × r_i
```

叉乘展开（ω 只有 z 分量）：

```
ω × r = (−w·y_i, +w·x_i)
```

所以

```
v_ix = vx_c − w·y_i
v_iy = vy_c + w·x_i
```

> 检查一下符号：w > 0（逆时针）时，位于 +x（车头）的轮子应该往 +y（左）走 ✓；
> 位于 +y（左侧）的轮子应该往 −x（后）走 ✓。和"绕中心逆时针转"的直觉一致。

### 第 3 步：轮子要朝哪、转多快

```
speed = √(v_ix² + v_iy²)
angle = atan2(v_iy, v_ix)
```

就这两行。到此为止是"理想的逆解"。

### 第 4 步：工程修正（下面三节）

理想解在数学上没错，但直接下发给电机会有三个问题：**舵机来回甩**、**舵机猛打**、**超速**。

## 4. 等效解翻转（考核点）

### 4.1 为什么会有两个解

舵角是**周期量**：把轮子转到 θ，和转到 θ+180° 并把轮子反转，对整车运动**完全等价**。

```
   θ = 170°                        θ' = −10°，轮速取反
      ╱ 轮子朝前上                    ╱ 轮子朝前下
     ●                              ●
   舵机只差 180° 的两个位置，滚出来的车体速度一模一样
```

### 4.2 不处理会怎样

假设上一周期舵角在 0°，新目标突然变成 170°：

- 不翻转：舵机要转 **170°**（大甩，慢、还会把车带得晃一下）；
- 翻转：目标是 170°−180° = **−10°**，舵机只转 **10°**，同时轮速取反。

所以规则是：

> **目标角与当前角相差超过 90°（再加一点回差），就选等效的另一支。**

### 4.3 代码里怎么判

```cpp
// 参考角：优先用上一次的目标（连续、无跳变），没有历史就用当前实测
float reference = has_last_ ? last_angle_[i] : steer_now[i];

// 从参考角转到「原始解」要转多少（归一化到 ±π）
float diff = robot::WrapPi(angle - reference);

// 超过 90° + 回差 → 换另一支：角度 +180°、轮速取反
if (magnitude > kSpeedDeadband && fabsf(diff) > (kHalfPi + kFlipMargin)) {
    angle += π;
    sign = -sign;
    diff = robot::WrapPi(angle - reference);   // 重新算，此时 |diff| 会变成 ~10°
}
```

两个细节：

- **回差（`kFlipMargin = 0.05 rad`）**：如果正好在 90° 附近抖动，没有回差会每周期翻来翻去，
  舵机会"抖"。加了回差后，翻过去之后要回退到 90°−2.9° 以下才会翻回来。
- **用"上一次目标"而不是"当前实测"做参考**：目标本身被速率限幅成连续量，比实测更平滑；
  而且第一帧没有历史时才退回用实测。

### 4.4 翻转之后轮速要取反

这是最容易漏的一步。翻转改变的是"轮子的朝向"，同一个车体速度对应的轮子转向当然要反过来。
代码里用 `sign` 变量单独记录，最后 `speed = sign * magnitude`。

> 单测里专门有一例：`从 0° 要求 170° → 应翻成 −10°、轮速为负、但实际滚动方向仍是 170°`。

## 5. 限幅与执行层门控

2026-10-27 修正：四轮按最大轮速**统一缩放**，保持比例；`angle` 限速，`desired_angle` 保留最终等效方向。
执行层以 `desired_angle−实测角` 判断是否超过约20°，超过则驱动电流归零并清驱动PID积分。
对齐后按余弦投影缩放；停机清除历史，恢复时从当时实测角起算。非有限输入/无效几何/计算溢出整组拒绝。


| 限幅 | 目的 | 参数 | 位置 |
|---|---|---|---|
| 舵角变化率 | 不让舵机"啪"地甩过去 | 10 rad/s（1ms 内最多 0.01 rad） | `max_steer_rate_` |
| 轮速 | 不超速、不失控 | 3.0 m/s | `max_wheel_speed_` |
| 低速死区 | 停车时不乱摆舵轮 | 0.02 m/s | `kSpeedDeadband` |

### 5.1 为什么舵角限幅要做在"目标"上

限幅的是**目标角**，不是电机的实际角速度。舵角环（PID）去追这个慢慢移动的目标，
实际转速自然就被限制住了，而且不会和 PID 打架。

### 5.2 为什么零速时要保持舵角

停车时 `v_ix = v_iy = 0`，`atan2(0,0)` 没有意义。如果直接算，四个轮子会随机指向某个方向
（数值上通常是 0），表现为"每次停车轮子都自己转正"，既难看又吵，还会磨轮胎。

所以代码里：

```cpp
if (magnitude <= kSpeedDeadband) {
    speed = 0;
    angle = 上一次的目标;   // 保持不动
}
```

## 6. 代码走读（`chassis_ik_solver.cpp`）

```cpp
void solve(motion, delta, steer_now, dt, out) {
    // ① 云台系 → 车体系
    const float vx_c = motion.vx * cos_d - motion.vy * sin_d;
    const float vy_c = motion.vx * sin_d + motion.vy * cos_d;

    for (每个轮组 i) {
        // ② 平动 + 转动
        const float v_ix = vx_c - motion.w * y_i;
        const float v_iy = vy_c + motion.w * x_i;

        // ③ 大小与方向（magnitude 恒正，方向单独用 sign 记）
        float magnitude = sqrt(v_ix*v_ix + v_iy*v_iy);
        float sign = 1.0f;
```

## 7. 怎么验证它对不对

### 7.1 单测（`tests/test_main.cpp`）

| 用例 | 期望 | 说明 |
|---|---|---|
| 纯前进 | 四轮速度矢量都是 (1,0) | 最基本的 |
| 原地左转 | 每个轮速度 = ω×r | 转动的力臂方向 |
| 云台左偏 90° + 前进 | 四轮速度矢量 (0,+1) | δ 旋转方向（**最容易错**） |
| 从 0° 要求 170° | 舵角 −10°、轮速为负 | 等效解翻转 |
| 单周期 | 舵角最多变 0.01 rad | 速率限幅 |
| 零指令 | 速度 0，舵角不变 | 死区 |
| 大速度 | 被限到 3 m/s | 轮速限幅 |

### 7.2 上车验证（10 秒版）

1. 把车架空（轮子离地）；
2. 分离模式，推前进 → 四个轮子都朝前、同向转；
3. 转云台 90°，保持推前进 → 四个轮子一起转向 90°（轮子朝侧面）；
4. 原地左转（拨轮） → 四个轮子组成"逆时针画圈"的姿态。

> 第 3 步是核心：**轮子方向应该跟着云台转，而不是跟着车头**。

## 8. 常见错误对照

| 现象 | 原因 | 改哪里 |
|---|---|---|
| 推前进车往后退 | 某个轮电机方向反了 | `ins_motor.cpp` → `kWheelDir` |
| 推前进车画斜线 | 某个舵角零点不准 | `ins_motor.cpp` → `kSteerAngleOffset` |
| 转云台后前进方向左右反 | 旋转矩阵符号 | `chassis_ik_solver.cpp` 第 1 步 |
| 舵机一直来回小幅抖动 | 目标在 90° 边界反复翻 | 加大 `steer_flip_margin` |
| 起步时轮子"蹭地" | 舵角没到位就驱动 | 调 `kSteerReadyAngle`（默认 20°） |
| 车原地缓慢自旋 | 四个舵角零点不齐 | 逐个标定 `kSteerAngleOffset` |
| 高速时方向发飘 | 轮速限幅太低 / 轮速环增益不够 | 先查机械，再整定 `ins_pid.cpp` |
