# 06 · 调车手册

> 新手从 `docs/12` 的Ozone主流程开始；原始审计见 `docs/13`、修复与硬件待验项见 `docs/15`，完整参数清单见 `docs/14`。

> 当前代码验证记录见 `docs/15`。本手册是待执行流程，不能代替台架记录。

## 1. 准备与上电确认

- 轮子架空，云台留出完整活动空间，准备可直接切断驱动电源的急停手段。
- 遥控器先开，右拨杆保持下档急停，摇杆与拨轮回中，再上电。
- 正常固件两板 `kDebugAlwaysFeedWatchdog=false`、`kEnableFaultInjection=false`。
- 两板均烧本次构建的配套固件，核对 ELF 构建标签与板上标志；只看到文件标签不代表烧录成功。
- 本版发送配置依据原接线图：底盘CAN1为GM6020，CAN2为M3508与板间总线；云台CAN1连接板间及yaw，CAN2连接pitch。配置集中在`board_wiring.hpp`；不要求为适配旧代码改线。接收机支持云台侧原始DBUS转发或底盘本地接收，须先以实际控制来源急停确认。

底盘上电、遥控失联或任何安全故障退回 Dead 后，需要再次收到本地有效急停档，才能授权起动。
保持急停时所有电机输入为零；全体在线、IMU 标定完成、当次采样有效、通信正常后，状态机经过恢复自检。
确认状态和操作区域后才解除急停。不能仅凭“已等 2.5 秒”判断允许起动。

## 2. 仅控制板检查

断开电机信号/驱动电源，只连接两板、遥控器和双板 CAN。
本步骤 **Dead 是正确结果**：没有电机反馈时禁止进入 Working。

| 检查 | 应观察到 |
|---|---|
| DBUS | 底盘 `isRemoteOnline()` 为 true；非法帧计数不持续增长 |
| IMU | `errorState()==0`，静止采样后 `isCalibrated()` 为 true；`isSampleValid()` 和 `isHealthy()` 正常 |
| 双板 | `isOffline()` 为 false；成功解码计数递增 |
| 电机门 | `areAllMotorsOnline()` 为 false，所有目标输入为零 |
| CAN 提交 | `canTxFailedCycles()` 不持续增长；没有接收端 ACK 时不能靠 HAL 入邮箱成功证明链路可用 |

正常接收机在底盘；云台可以利用底盘报告的 DBUS 在线状态保活。仅把接收机接云台不能授权底盘控制。

## 3. 方向、零点与单电机测试边界

最新参数已按补全版说明书 6.2 预置，来源与 SHA-256 见 `docs/00`。先核对接线、ID 和原始反馈。
在可靠隔离驱动力、仍能读取编码器的条件下，被动移动轮组/关节，观察正方向与零位；
不能安全隔离驱动力时先停止这项操作。不得在带力矩状态下用手掰机构。

| 对象 | 被动检查 |
|---|---|
| 轮电机 | 按定义的正向转轮，`vel()` 符号应正确 |
| 舵轮 | 俯视逆时针为角度正向；轮面朝前时 `angle()` 应接近零 |
| yaw | 枪口与车头重合时关节角接近零；逆时针为正 |
| pitch | 枪口水平时关节角接近零；抬高为正；记录机械行程并留软件制动余量 |

**当前正常固件没有孤立单电机主动测试入口。** 只接一个电机无法通过全电机在线门；
调试器手动 `setInput()` 会被下个 1 ms 控制周期覆盖，不能作为可执行的方向测试。
不得增加“跳过状态机、只保留急停”的临时分支。

若团队考核要求先单板/单电机主动验收，需要先落实独立台架方案：有效 DBUS、明确测试档和操作者持续授权、
急停、所选电机反馈在线、低电流/电压限幅、短超时、退出清零，以及明确的状态机资格。
团队确认此流程后再实现和验证；本轮未提供绕过安全条件的测试固件。
发现方向或零点与说明书不一致时先记录证据并由团队核对，不私自更改电调设置。

## 4. 全系统架空闭环

接好全部电机与两板，按第 1 节完成起动确认。首次保持低幅遥控指令，依次进行：

1. 分离模式前后平移：检查四轮符号、舵角和轮速。
2. 横移：检查 `desired_angle` 与实测角；未对准最终方向超过约 20° 时，驱动输入应为零。
   `angle` 是限速后的伺服目标，不能用它代替最终方向判定。
3. 平移叠加旋转：四轮超速时应同比缩放，记录目标与反馈，检查侧向拖拽。
4. 云台小幅 pitch/yaw：先确认软件限位在机械边界内；yaw 可连续旋转，pitch 到边界不得继续向外顶。
5. 跟随模式与小陀螺：记录方向、收敛、超调和电流；坐标公式冲突按 `docs/00` 在架空状态确认。

每次只改一组 PID，记录前后响应。增益属于待整定初值；代码通过不能证明机械闭环稳定。
完成故障注入、限位、电流温升和整定验收后，才进入团队许可的低速落地测试。

## 5. 失效与恢复

| 故障 | 软件预期 | 必须实测的内容 |
|---|---|---|
| 遥控急停 | 有效急停帧被处理后，下一个控制周期清零输入 | DBUS 到 CAN 零指令的延迟、实际停机时间 |
| 遥控掉线 | 超过 100 ms 在线阈值后退出 Working；无新鲜遥控依据则停喂狗 | 约 100 ms 保活窗口再叠加 IWDG 超时；实测复位原因与电机卸力 |
| 坏 IMU 样本 | 当次 `isSampleValid=false`，退出 Working | 恢复轨迹、SPI错误/设备时钟冻结/DRDY停更与20ms过期停机；内部异常同时伪造新鲜度仍需独立验证 |
| 关键 CAN 编码/提交失败 | 本周期末锁存、Dead、清零；后续周期重试零指令 | 零帧是否真正送达、电机自身失联动作 |
| 连续 CAN 失败 | 连续 10 ms 后停止喂狗 | IWDG 实际复位时间；总线恢复时有无旧命令残留 |
| CAN 恢复 | 需有效急停且所有关键帧连续 100 ms 成功提交，解除锁存后再自检 | 正常档保持时不得自行恢复出力 |
| 电机/对板掉线 | 超过在线阈值退出 Working、清零 | 物理停机、制动距离和电机失联保护 |

`HAL_OK` 只证明报文进入邮箱，不能证明电机已收到。CAN 断线时连零指令也可能送不到；
必须验证电机端失联策略和驱动电源急停，禁止据软件清零宣称物理安全。

看门狗核对：正常模式下触发断遥控/任务卡死，重连读 `g_reset_by_iwdg`。
隔离驱动电源后可做反证：临时把 `kDebugAlwaysFeedWatchdog=true`（无条件喂狗），复位应消失；
完成后改回 false 重烧并核对。方向不能写反。详细记录见 `docs/08`。

## 6. 调试故障定位

| 现象 | 先检查 |
|---|---|
| 一直 Dead | 有效遥控急停确认、全部在线、IMU 标定/当次有效性、`canTxHealthy()` |
| 故障解除后不动 | 是否仍有 CAN 锁存；在急停档保持成功发送超过 100 ms，再等待自检 |
| 两板急停解除异常 | G2C 只上报云台本地急停，C2G 为组合急停；两板须烧配套版本 |
| 舵轮偏转时仍驱动 | 最终等效角、实测角及驱动 PID 积分，不只看限速目标 |
| CAN 计数增长 | 接线/终端电阻/负载/邮箱及 bus-off；先停机定位，勿仅降低帧率掩盖问题 |

交付前运行 `tests/run_tests.ps1`，完成两板构建，核对安全开关，保存台架记录。
主机测试与构建结果、硬件尚未执行项分别记录，不能相互替代。
