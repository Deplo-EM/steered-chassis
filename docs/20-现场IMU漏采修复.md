# 20 · 现场 IMU 漏采修复

2026-11-13。使用 Ozone 在云台会话只读观察：合法 DBUS 帧持续增长，板间在线；云台 `state_` 在 `kDead` 与 `kResurrection` 之间变化。`stale_gyro_` 持续增长，SPI、设备时钟回退和样本量级拒绝计数未见对应增长。观察到的 CAN 发送失败历史累计不为零，但读取时 CAN 故障未锁存。此时云台不能稳定完成 500 ms 自检，足以挡住底盘 `Working`。

[Bosch BMI088 手册](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bmi088-ds001.pdf) §4.7.2 规定陀螺仪就绪脉冲约 280–400 µs。原代码每 1 ms 读一次该位，可能反复错过。主机用真实驱动和 SPI 模型复现：传感器持续出样，轮询一直看不到就绪位，旧代码不能完成标定。

两板改用 BMI088 陀螺仪 FIFO 确认新样本。每轮最多消费 4 帧，按硬件采样率逐帧积分；空 FIFO 不续期、不重复积分。积压或溢出时清队列、撤销样本有效性并重新标定。SPI 传输失败、IMU 20 ms 新鲜度、急停和看门狗保护保留。软复位后等待手册要求的 30 ms 再写配置；先读温度等字段，再消费 FIFO，单次温度传输错误不丢已入队样本。真正的 FIFO 突发传输中断时，已读的半帧无法补回。

两板 ELF 均已重新生成。当前 Ozone 会话仍连接着修改前的程序；在保持急停、隔离驱动力的条件下结束旧会话，重新打开对应的 `.jdebug`，用 **Download & Reset Program** 更新各板，核对 **Program & Verify**。两板固件都更新后，四轮架空并固定，先开遥控器、保持右下急停，再给整车上电并静置。先确认云台不再反复回 `Dead`、底盘进入 `kWorking`，再解除急停。没有修改接线、PID 或三模式指令。

两板构建退出码0、无编译警告、标签SAFE-BUILD。全套主机回归1335项、0失败，其中两板BMI088传输各46项。实车仍未烧录本次修订；不把离线通过等同于试车通过。见`audit_evidence/imu-fifo-2026-11-13.json`。
