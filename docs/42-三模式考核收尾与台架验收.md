## 这次改了哪几条路径

| 现象 | 查到的路径 | 这版行为 |
|---|---|---|
| 直行舵轮歪，转向偏慢 | v22 开了 `ROBOT_ACCEPT_STUCK_STEER` 与 `ROBOT_STEER_BREAKAWAY`；旧对齐放行阈值约 17°，配合绕过可以边歪边驱动。 | 四轮都到位才起步；测量角差和限速轨迹角差都要满足。0.12 rad 重新放行，0.20 rad 撤销；接近边界四轮一起降速，0.08 rad 内为满比例。舵角轨迹 10→12 rad/s，电流版 PID 初值 6000/400/120→7200/800/150，留实测速率阻尼，电流上限仍为 1.2 A。关闭摩擦前馈和脉冲，保留等效解翻转。 |
| 小陀螺合推后只剩平移 | 旧代码已经生成非零角速度。原轮速整体限幅可能把旋转一起压低；最低旋转档叠加平移还会受轮速环电流饱和、舵角偏差及地面负载影响。仅凭这次现象无法确认哪一项先发生。 | 旋转先分配轮速，余量统一给同方向平移。小陀螺平移目标最多 0.60 m/s、平移斜坡 2.0 m/s²，最低旋转请求仍为 1.5 rad/s。轮速分配以同一刚体关系计算，见 [FIRST 官方舵轮运动学说明](https://docs.wpilib.org/en/stable/docs/software/kinematics-and-odometry/swerve-drive-kinematics.html)。 |
| 按压 Pitch 后会 Dead | PID 输出可到 5.0 N·m，B22 重力项再叠加，电机接口限到 3.5 N·m 并返回越界，继而两板撤权。 | 重力项和反馈合计按实际电机上限做抗饱和，正常饱和继续控制；按共同关节限位 −0.47～+0.70 rad 管理目标，已越界时只允许朝内出力。摇杆可主动接管自动抬平。 |
| 快速前后左右动时偶发 Dead | 既有现场取证包含一拍 `kAccLow`；原控制层单个拒绝样本立刻锁存，不代表所有同类停机都来自它。 | 已有授权时，只对低模长 `kAccLow` 且上一份合格姿态、设备时钟、陀螺和加速度均在 8 ms 窗口内，暂用合格状态；坏值不进融合，云台冻结 Yaw 目标增量。超时、传输错、时钟/FIFO 错、失联、真实堵转、无效角度、急停仍撤权。首跑版维持原 IMU 判据。 |
| 小陀螺平移不直 | 速度方向按云台的坐标系；云台世界朝向变化时，期望平移方向也会随它变。即使云台朝向不变，轮位错配、零点、刮蹭和打滑仍能改变轨迹。 | 保留坐标关系与最新实车控制符号；合推平移只统一缩放，不扭转指令方向。先做下面的信号判别，路面轨迹留到最后验收。 |

当前 v22 源码的轮、舵 ID 均为 `{1,2,3,4}`；这是本次候选采用的映射。38、39、41 号的 `{3,4,1,2}` 属于较早版本，不能直接当作本版的实车证据。未改 ID、舵角零点、外部减速比、电机内部参数或 CubeMX。四组实物仍按左前、左后、右后、右前分别确认驱动和转向。

## 用 Ozone 逐项验收

先完成 [38 号放行清单](38-四轮版下地放行清单.md) 的机械、台架与停机部分。右后轮干涉未解决或独立断动力未验证时，暂停带动力试车；此前两次 Yaw 失控说明不能只靠看门狗复位或软件急停兜底。机械检查隔离动力，参见 [HSE 设备维护指导](https://www.hse.gov.uk/work-equipment-machinery/maintenance.htm)。可先对照软件停机路径；不带动力手压云台来验限位。

1. **急停和驱动停止先验。** 在固定架空台架核对遥控急停、掉线及两轴确实脱力。先分别确认舵角反馈和轮速反馈属于同一个物理轮位。`Working` 只是完成自检。
2. **舵角直行与转向。** 左拨杆上档、先让云台朝车头。观察 `robot::diag::g_chassis_dbg` 的 `steer_desired`、`steer_target`、`steer_feedback` 与 `align_blocked_mask`。从轻推前后开始，再做 90° 换向；记录实际舵追到目标 0.08 rad 内所用时间。目标到位但实测不跟，按轮位查方向、零点、干涉及电流；实测反馈显示 0 但轮子物理摆歪，先校准零点。允许等效翻转时舵角与轮速方向同时变化。
3. **快速拨杆或 Pitch 停机。** 在安全停住后查看底盘 `s_robot.last_dead_`、`s_robot.last_imu_dead_`，或云台 `robot::diag::g_gimbal_dbg.last_dead_reason` / `last_dead_tick_ms`。底盘 `causes=8` 是 IMU 分支，需继续看原因和当刻样本；云台 `2` 是 IMU，`4` 是电机反馈，`32` 是发送，`64` 是执行控制。`drive_ready=0` 而仍 Working 通常是等待轮组对齐，和 Dead 是两件事。正常限位用遥控轻推验证，不用手跟带动力电机对抗。
4. **小陀螺合推最后测。** 台架检查指令；实际偏航速度与平移轨迹应在机械与停机放行后测。云台朝向保持不变、拨轮中位，先观察无平移，再加少量前进，最后再增加平移。比较 `ramped_w`、`drive_w_request`、`gyro_z_radps` 和 `alignment_scale`：前两项有值且陀螺近零，检查轮速实测、轮组方向和载荷；第一项有值而第二项近零，优先看对齐门。陀螺 Z 的符号按实车坐标核实。只有前述项过关才测走直线。

## 构建复现

```powershell
cmake -S Chassis -B Chassis/build/competition-finish -G Ninja -DCMAKE_BUILD_TYPE=Debug -DROBOT_COMPETITION_FINISH=ON -DROBOT_STEER_CURRENT_FIELD=ON
cmake --build Chassis/build/competition-finish
cmake -S Gimbal -B Gimbal/build/competition-finish -G Ninja -DCMAKE_BUILD_TYPE=Debug -DROBOT_COMPETITION_FINISH=ON -DROBOT_PITCH_GRAVITY_FF=ON
cmake --build Gimbal/build/competition-finish
pwsh -NoProfile -File tests/run_tests.ps1
```

候选的构建规则拒绝排除轮、对齐或堵转旁路、禁翻转、摩擦补偿与脱困脉冲；云台保留 B22 重力前馈并与反馈一起限幅。主机检查不会验证机械条件、真实制动距离、负载下转向时间或全车实地验收。

本轮复核：两板 GNU Arm 构建退出码 0，已读取两份 ELF 的各自标签；全套主机测试 2493 项、0 失败。轮位对齐、合推后的轮速分配、IMU 短时续用与明确传输故障、Pitch 正常饱和（含 B22 重力项）均有回归。v22、B22 及三份首跑历史产物哈希与已有记录一致。
